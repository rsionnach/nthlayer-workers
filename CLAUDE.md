# nthlayer-workers

Unified Tier 2 background computation package for the NthLayer ecosystem. Houses all worker modules: observe, measure, correlate, respond, learn. Communicates with nthlayer-core exclusively via HTTP API — never accesses the SQLite store directly.

## Conventions

- Each worker module exposes its own `cli.py` with a `main()` function and is invoked via `uv run --directory nthlayer-workers`
- Top-level `nthlayer-workers serve` starts all registered modules; observe split into three modules (ObserveCollectModule/ObserveDriftModule/ObserveTopologyModule) as of P3-B.2; correlate split into three modules (CorrelateSessionModule/CorrelateTopologyModule/CorrelateContractModule) as of P3-D.2; MeasureModule implemented [P3-C.1]; RespondModule implemented [P3-E.1] — structural migration complete (I/O → core API, CLI → poll-driven, SQLiteVerdictStore/SQLiteContextStore removed from worker path); P3-E.2 (Instructor), P3-E.3 (approval-verdict poll+resume), P3-E.4 (notifications), P3-E.5 (on-call) are follow-up beads; learn: LearnOutcomeModule (60s) + LearnRetrospectiveModule (30s) implemented [P3-F.1]
- One module = one responsibility; no internal timers — use separate module registrations at different intervals instead
- Never access nthlayer-core SQLite store directly — all reads/writes go through `CoreAPIClient` HTTP API
- Verdict data model lives in `nthlayer_common.verdicts`; learn module only adds analytical operations on top
- Decision records (content-addressed audit trail) use `nthlayer_common.records.SQLiteDecisionRecordStore`
- Align internal types with canonical shapes rather than writing adapters — adapters are for code you don't own
- `ServiceSLO(service: str, slo: SLODefinition)` carrier in observe/slo/ bridges manifest-level service context to the collector; not an adapter, just adds the one field the common SLODefinition legitimately omits
- `spec_loader.py` uses `nthlayer_common.manifest.load_manifest()` (canonical parser); local SLODefinition deleted in P3-B.1
